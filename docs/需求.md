查询筛选组件添加，现在需要列出方案。
需求：
1.默认存在两个输入框表单项。
2.表单项可添加组件类型：复选按钮组、级联选择器、日期选择框、输入框、数字表单项、单选框组、下拉选择器。
3.组件配置通用：设置布局方式：一列、二列、三列、四列；设置默认值、设置占位提示placeholder（输入框下拉等区域可以设置）；设置label名和field名；设置是否必填。
4.复选按钮组：设置排列方式（水平排列、垂直排列）；数据配置（手动和请求数据）。
5.级联选择器：设置级联数据（输入JSON或者请求）。
6.日期选择框：选择类型（日期/日期区段）；且支持禁用之前的日期选择。
7.输入框：设置最大长度；设置附加内容。
8.数字表单项：设置最大值、最小值；设置单位；设置小数位。
9.单选框组：设置排列方式（水平排列、垂直排列）；数据配置（手动和请求数据）。
10.下拉选择器：设置模式（单选、多选）；设置是否可以搜索；数据配置（手动和请求数据）。
11.组件配置添加数据交互tab，同自定义表单的提交，支持api接口和事件路由。

要求：
1.请求数据现在项目有现成的组件。手动配置也需要封装个组件，支持通过按钮添加数据项，数据项分为字段名和字段值。
2.布局方式通过flex修改。

列出详细的方案，以及是否有疑点。

详细方案：

一、组件定位
新增一个独立的“查询筛选组件”，不修改现有搜索组件与自定义表单组件。
组件用于搭建查询条件区域，支持多种筛选字段、灵活布局、手动或请求数据源，并支持通过 API 接口或事件路由发起查询。

二、范围说明
本次方案包含以下能力：
1. 默认生成 2 个输入框表单项。
2. 支持新增多种筛选字段类型。
3. 支持字段通用配置和类型专属配置。
4. 支持手动数据源和请求数据源。
5. 支持独立的“数据交互”Tab。
6. 支持 API 接口提交和事件路由提交。
7. 支持空条件直接查询全部。
8. 布局通过 flex 实现。

本次方案不包含以下能力：
1. 不包含成功提示、失败提示。
2. 不包含成功后重置、失败后重置。
3. 不改动旧搜索组件行为。
4. 不改动旧自定义表单组件行为。

三、组件配置结构
查询筛选组件配置面板建议拆分为两个 Tab：

1. 组件配置
- 配置筛选字段列表
- 配置查询按钮、重置按钮
- 配置布局与样式相关参数

2. 数据交互
- 配置提交方式
- 配置 API 接口
- 配置事件路由

四、默认初始化
新增查询筛选组件时，默认生成 2 个输入框表单项。

建议默认字段如下：
1. 字段 1：label = 关键字，field = keyword
2. 字段 2：label = 名称，field = name

默认按钮配置建议如下：
1. 查询按钮文案：查询
2. 重置按钮文案：重置
3. 默认显示重置按钮：是
4. 按钮对齐方式：右对齐

五、支持的字段类型
查询筛选组件支持以下字段类型：
1. 输入框
2. 复选按钮组
3. 级联选择器
4. 日期选择框
5. 数字表单项
6. 单选框组
7. 下拉选择器

六、字段通用配置
每个字段统一支持以下通用配置：
1. label 名
2. field 名
3. 是否必填
4. 布局方式：一列、二列、三列、四列
5. 默认值
6. placeholder

说明：
1. placeholder 仅在输入框、下拉选择器等适用组件上生效。
2. field 必须唯一。
3. 默认值需与字段类型匹配。

七、字段专属配置
1. 输入框
- 最大长度
- 附加内容
- 可扩展为前附加 addonBefore
- 可扩展为后附加 addonAfter

2. 复选按钮组
- 排列方式：水平排列、垂直排列
- 数据配置方式：手动配置、请求数据

3. 级联选择器
- 数据配置方式：输入 JSON、请求数据
- JSON 模式下直接填写级联树结构
- 请求模式下通过字段映射生成级联树

4. 日期选择框
- 选择类型：日期、日期区段
- 支持禁用之前日期选择

5. 数字表单项
- 最大值
- 最小值
- 单位
- 小数位

6. 单选框组
- 排列方式：水平排列、垂直排列
- 数据配置方式：手动配置、请求数据

7. 下拉选择器
- 模式：单选、多选
- 是否允许搜索
- 数据配置方式：手动配置、请求数据

八、数据源配置方案
1. 手动数据源
手动配置需要封装独立组件，建议命名为 OptionListEditor。

功能要求：
1. 支持通过按钮新增数据项。
2. 每个数据项包含两个字段：label、value。
3. 支持删除数据项。
4. 支持非空校验。
5. 支持 value 唯一校验。

适用字段：
1. 复选按钮组
2. 单选框组
3. 下拉选择器

2. 请求数据源
请求数据优先复用项目现有请求参数配置组件。

建议复用内容：
1. 接口地址
2. 请求方式
3. 请求头
4. Query 参数
5. 调试功能

请求数据需要补充字段映射配置：
1. labelField
2. valueField

级联选择器额外增加：
1. childrenField

说明：
1. GET 请求时明确禁止配置 Body。
2. POST / PUT / PATCH 时允许配置 Body。

3. 级联 JSON 数据
级联选择器支持直接输入 JSON 数据，数据结构为标准树形结构，例如：

```json
[
  {
    "label": "浙江省",
    "value": "zj",
    "children": [
      {
        "label": "杭州市",
        "value": "hz"
      }
    ]
  }
]
```

九、布局方案
布局方式通过 flex 实现。

外层容器建议：

```scss
display: flex;
flex-wrap: wrap;
gap: 12px 16px;
```

字段宽度规则：
1. 一列：100%
2. 二列：calc((100% - 16px) / 2)
3. 三列：calc((100% - 32px) / 3)
4. 四列：calc((100% - 48px) / 4)

按钮区域规则：
1. 独占一整行。
2. width: 100%。
3. 按钮默认右对齐。
4. 与字段区域分开布局。

移动端建议：
1. 小屏幕统一降为 1 列显示。

十、数据交互 Tab 方案
查询筛选组件需要新增数据交互 Tab，交互方式参考自定义表单的提交能力，但仅保留提交相关配置。

包含内容：
1. 提交方式：API 接口、事件路由
2. API 配置
3. 事件路由配置

不包含内容：
1. 成功提示
2. 失败提示
3. 成功后重置
4. 失败后重置

1. API 接口提交
配置项：
1. 请求方式：支持 GET、POST、PUT、PATCH
2. 接口地址
3. 请求头配置
4. Query 参数配置
5. Body 参数配置
6. 调试按钮

提交规则：
1. GET 请求时，查询条件合并到 Query 参数中。
2. GET 请求时，明确禁止配置 Body。
3. 非 GET 请求时，查询条件合并到 Body 中。
4. 空条件允许直接发起请求。

2. 事件路由提交
事件路由发送结构与旧搜索组件保持一致：

```ts
{
  from,
  to,
  type,
  payload: {
    action: 'search',
    data: searchParams
  },
  timestamp
}
```

说明：
1. 空条件查询全部时，data 为 {} 或仅包含默认值字段。
2. 不修改旧搜索组件的数据结构规范。

十一、运行态提交规则
查询筛选组件运行态建议基于 antd Form 实现。

查询流程：
1. 点击查询按钮。
2. 执行表单校验。
3. 允许空条件提交。
4. 格式化字段值。
5. 根据提交方式发起 API 请求或事件路由。

重置流程：
1. 点击重置按钮。
2. 调用 form.resetFields()。
3. 恢复到字段默认值状态。

十二、字段值格式化规则
1. 输入框
- 提交字符串

2. 数字表单项
- 提交 number

3. 单选框组
- 提交单值

4. 复选按钮组
- 提交数组

5. 下拉选择器
- 单选模式提交单值
- 多选模式提交数组

6. 级联选择器
- 提交选中路径数组

7. 日期选择框
- 单日期时，按字段名提交
- 日期区段时，不直接提交数组，拆分字段提交

日期区段提交格式如下：

```ts
{
  startDate: '2026-03-01',
  endDate: '2026-03-31'
}
```

如果后续扩展到时间区段，则提交格式如下：

```ts
{
  startTime: '2026-03-31 08:00:00',
  endTime: '2026-03-31 18:00:00'
}
```

说明：
1. 当前日期区段按 startDate、endDate 提交。
2. 不使用原字段名提交区间数组。

十四、推荐实现方式
推荐采用以下实现思路：
1. 新增独立组件 queryFilter。
2. 字段配置与运行态渲染完全独立。
3. 数据交互配置抽为可复用块。
4. 请求参数配置复用现有能力。
5. 手动数据配置新增独立编辑组件。
6. 布局统一使用 flex。

这样做的优点：
1. 不影响旧组件。
2. 结构清晰。
3. 维护成本低。
4. 便于后续扩展更多筛选控件。
