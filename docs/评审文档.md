# 评审文档

## 发现的问题

1. **模型评估页不会响应模型 ID 变更**
   - 位置：`src/pages/ProjectWorkflow/components/ModelTraining/EvaluationReport/index.tsx:181`
   - 详情：`useEffect` 依赖数组为空，仅在组件挂载时调用 `getReportData`。当用户在同一路由下切换 `modelId`（例如通过筛选模型或回到列表再进入）时，该组件不会重新请求，页面继续展示旧模型的评估结果。
   - 影响：用户看到的评估得分、误检数据等都可能与当前选中的模型不符，容易造成误判。
   - 建议：把 `modelId`（或 `searchParams`）作为依赖，或在路由参数变化时手动清理并重新调用 `getReportData`，确保切换模型后自动刷新。

2. **评估指标为 0 时被当成“无数据”处理**
   - 位置：`src/pages/ProjectWorkflow/components/ModelTraining/EvaluationReport/index.tsx:194-210`
   - 详情：`data?.total_score ? ... : 0`、`data?.precision ? ... : 0` 等判断把 0 当作 falsy，从而不渲染圆环，并把展示值格式化成整数 “0”。如果后端返回 0（合法结果），页面就显示为空状态。
   - 影响：真实的 0 分或 0% 会被误认为没有数据，导致评估报告在最差情况下完全不显示图形反馈。
   - 建议：使用 `data?.precision !== undefined` 等显式判断，只在 `null/undefined` 时判定为缺失数据，其余情况正常渲染并保留两位小数。

3. **标签工作台分页跳转的最大页数计算与 PAGE_SIZE 不一致**
   - 位置：`src/components/Bussiness/KonvaAnnotatorModal/index.tsx:590-594`
   - 详情：输入页码的校验使用 `Math.ceil(totalObj[activeTab] / 20)`，而当前分页大小常量是 `PAGE_SIZE = 21`。当样本总数超过 20 且不能被 21 整除时，会允许跳到并不存在的页码或阻止跳到真实的最后一页。
   - 影响：用户键入页码跳转时可能进入空白页或者无法跳到数据实际存在的最后一页，分页体验异常。
   - 建议：使用统一的 `PAGE_SIZE` 常量计算最大页数，例如 `Math.ceil(totalObj[activeTab] / PAGE_SIZE)`。

4. **数据集列表 Mock 接口没有按照项目 ID 过滤**
   - 位置：`mock/routes/dataset.js:69-76`
   - 详情：`/dataset/list` 接口里把按 `project_id` 过滤的实现注释掉，直接返回全部 `datasetList`。前端即使传入项目 ID 也得不到对应项目的数据。
   - 影响：在联调或演示环境中，同一个项目页面会出现其他项目的数据，无法模拟真实的算法仓库场景。
   - 建议：恢复 `datasetList.filter(item => item.project_id === projectId)` 逻辑，并在 `project_id` 不合法时返回空数组或错误提示。

5. **工作台上的筛选控件只更新本地状态但从不驱动数据**
   - 位置：`src/pages/DataBoard/index.tsx:245-316`
   - 详情：页面定义了 `setSelectedLocation`、`setDateRange` 并在 `handleLocationChange`、`handleDateRangeChange` 中更新，但这些状态没有被用来过滤任何列表或图表。注释中也标明“实际应用中会根据…筛选”，说明目前是空实现。
   - 影响：用户在工作台上使用位置/时间筛选不会看到任何数据变化，容易误以为系统卡死或数据错误。
   - 建议：将筛选条件参与到 `loadData` 的请求或对 `alertData`、`resourceData` 做前端过滤；在功能尚未实现前应隐藏相关 UI 或添加禁用提示，避免误导。

如需更深入的修复方案或协助落地，请进一步沟通需求场景。
