里程碑规划
当前设计方案，仅支持在表单容器里进行编排，不支持单独组件配置及事件对接。

M0 架构冻结与工程骨架
周期建议：3 到 5 天。
目标：把新体系的边界和骨架搭起来。
内容：新增 nativeForm 的 WidgetType、默认配置、空白运行时组件、空白设计器壳子、左侧组件库“表单”tab、DSL v1 类型、manifest 注册接口、设计器独立 store。
涉及重点文件：src/types/index.ts、src/store/useStore.ts、src/components/WidgetDrawer/index.tsx。
验收标准：页面里能添加一个 nativeForm，能打开空白设计器，能保存一份空 schema，不影响旧 customForm。

M1 设计器基础闭环
周期建议：1 周。
目标：让 nativeForm 真正具备“可编辑”的基础能力。
内容：实现 NativeFormDesigner 主壳、物料面板、表单画布、选中态、节点插入、删除、排序、右侧 FormFieldConfigPanel、schema 保存与回显。
这一阶段先不追求复杂字段，先保证编辑闭环。
验收标准：能从“表单”tab 拖入基础节点到表单内部，保存后再次打开还能还原。

M2 基础字段物料与运行时渲染
周期建议：1 到 1.5 周。
目标：完成第一批常用字段，打通设计态到运行态。
内容：实现 input、textarea、inputNumber、select、radioGroup、checkboxGroup、datePicker、timePicker、switch 的 manifest、默认节点、属性面板、Antd 6 运行时 renderer。
同时支持字段基础属性：label、name、required、placeholder、defaultValue、disabled、hidden。
验收标准：能设计并运行一张基础表单，正确收集值和展示校验。

M3 数据源与高级输入字段
周期建议：1 到 1.5 周。
目标：补齐常见业务录入能力。
内容：实现 cascader、upload，并给 select、radioGroup、checkboxGroup、cascader 增加“手动选项 + 接口请求”两种数据源模式。
同时补齐默认值解析、接口选项映射、请求参数配置。
建议复用 portal 现有 API 配置交互风格，但逻辑落到新模块里，不侵入旧 QueryFilterFieldBuilder。
验收标准：能完成带接口选项、级联选项、文件上传的表单设计与运行。

M4 布局组件与子表格
周期建议：1.5 到 2 周。
目标：让表单从“字段列表”升级成“结构化设计器”。
内容：实现 group、grid、gridColumn、button、subTable。
这一阶段要补中间画布的容器拖拽、大纲树、节点嵌套、运行时嵌套渲染。
subTable 单独作为重型节点处理，支持列配置、行增删、子字段渲染。
验收标准：能设计分组、多列、子表格的复杂表单。

M5 提交、事件与动作体系
周期建议：1 周。
目标：把表单的“交互闭环”补完整。
内容：实现 submitButton、resetButton、普通按钮动作；实现 submitConfig；支持 API 提交、EventRouteConfig、Wujie bus。
建议统一成 NativeFormEventDispatcher + NativeFormSubmitService，不要让字段直接耦合 bus。
事件建议至少支持：init、valueChange、submit、submitSuccess、submitError、reset、fieldChange、fieldClick。
验收标准：一张表单可以对接口提交，也可以向其他微应用发事件。

M6 联动规则与条件逻辑
周期建议：1.5 到 2 周。
目标：覆盖大部分动态表单场景。
内容：实现声明式规则引擎，不上脚本引擎。
第一批规则建议支持：visible、disabled、required、setValue、reloadOptions。
同时实现规则配置面板、依赖关系处理、循环保护、运行时规则执行。
验收标准：能完成常见条件联动，不依赖 Formily reactions。

M7 体验强化、模板能力与稳定化
周期建议：1 到 1.5 周。
目标：让它成为可长期维护的正式能力。
内容：增加设计态/预览态切换、schema 校验、版本号与迁移器、本地模板、复制节点、导入导出 JSON、错误提示、边界校验、基础测试和文档。
如果还有业务专属字段，这一阶段再按 manifest 扩展，不回头改框架。
验收标准：团队能稳定新增表单物料，设计器具备生产可用性。

推荐里程碑

M1 配置模型重构
新增 layout、appearance、itemProps、styleProps 字段；补默认值、序列化、字段工厂。

M2 容器配置完善
补表单容器的布局与样式属性，先让运行态和设计态都吃到 labelAlign、colon、size、variant、borderRadius、backgroundColor。

M3 通用字段配置完善
补通用字段基础属性、表单项属性、字段样式属性，并在运行态 Form.Item 和控件层真正生效。

M4 高优先级字段专属属性
先做 input、textarea、inputNumber、select、radioGroup、checkboxGroup、upload、button。

M5 容器字段专属属性
补 group、grid、subTable 的专属配置和设计态预览。

M6 manifest 收口
把“哪些属性显示、哪些类型支持、哪些属性序列化”统一收口到 manifest，清掉无效配置入口。
